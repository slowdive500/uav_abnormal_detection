# crowd_temperature：移动来源温度巡检

这套实验重点观察**来源移动、采集位置差异和动态参与**。原始数据由作者结合真实出租车参与记录、位置、天气和来源误差生成温度，我们将稳定参与者映射为虚拟 UAV，在区域网格内组织报告任务。

数据说明来自 [Queen’s University](https://www.queenstrl.ca/datasets.html)，原文件通过 [IEEE DataPort](https://ieee-dataport.org/open-access/crawdad-queensucrowdtemperature) 获取。本机使用用户提供的原版 CSV，文件 MD5 为 `8edf0ea0427d9e961ce77ca0c9a0d2f0`，与上游记录一致。

## 原始数据

文件有 5,030 行、289 个来源，覆盖 2014-02-01 至 02-04，六列为：

```text
Taxi ID, Date, Time, Latitude, Longitude, Temperature
```

温度、经纬度和来源身份直接进入报告转换。文件没有区域 ID、独立参考温度或逐报告故障标签；任务网格由实验明确划定，原始异常状态保存为未知，不补造参考真值。

解析器处理两种日期编码：`02-03-14` 按月-日-年，38 行 `03/02/2014` 按日/月/年。时间中的 `+01` 提供时区偏移，转换后同时保留原始采样起止时间。

## 任务怎样构造

当前 Crowd v2 协议在 `configs/datasets/crowd_temperature.yaml` 中，将纬度 `[41.78, 42.00]`、经度 `[12.36, 12.64]` 划分为 **2×2 网格**。每个网格是一个巡检任务，罗马当地时间每 **30 分钟**形成一轮报告。报告提交时刻取区间右端点，并转换为 UTC 秒。

同一来源、网格和时段中的温度取均值，条件使用平均经纬度，另保存样本数和最后采样到提交之间的时间差。这个值表示该来源在半小时内实际采样的均值，不是右端时刻的瞬时温度真值。适配器不插值、不复制样本，也不补出缺席来源。网格变粗后仍保留实际位置条件，来源位置差异没有被替换为网格中心。

默认 `profile: standard` 使用前 **75 个训练时隙中出现的全部 164 个来源**，不再设置 32 个来源的上限。所选 3,701 条原始记录聚合为 **3,106 份报告、189 个实际有报告的时间片**。`profile: full` 当前使用相同的训练前缀来源集合。其余 125 个来源在训练前缀之后才出现；原始文件保留其记录，但固定来源词表的三方法比较不使用这些未来来源。

训练、验证、校准、测试按时间先后取 40% / 10% / 30% / 20%。来源选择前缀与训练集均截止于 `2014-02-02 12:30 UTC`，所有选定来源都在训练集中实际出现。修改分桶或划分时必须重新核验这一关系，不能沿用旧的 `source_selection_first_slots`。

| 阶段 | 报告数 | 时间片 | 可评分任务窗口 | 可评分报告 |
|---|---:|---:|---:|---:|
| 训练 | 1,243 | 75 | 162 | 1,042 |
| 验证 | 265 | 19 | 30 | 186 |
| 校准 | 886 | 57 | 97 | 731 |
| 测试 | 712 | 38 | 93 | 630 |

以上是基于参与和条件完整性计算的覆盖数量，使用两轮窗口、末轮至少三个来源、相邻轮间隔不超过 `1800.1` 秒；不是检测成功率。划分之间不共享窗口历史。

校准分配 30% 是为了满足**有效校准轮数预算**。同一任务的抽样轮次至少相隔一小时，每轮先按身份规则抽取一份报告，再检查评分是否可用。按当前数据覆盖，评分有限时可用 51 个单元；`alpha=0.05` 最多核验并去除 2 个，因此保留 49–51 个。实际运行须检查保留数量至少为 40。增加同轮来源不等于增加校准轮次；时间隔离也不证明时序数据满足交换性。候选分桶、网格的覆盖比较及来源归属核验保存在 `environment/crowd-redesign-coverage.json`。

## 导入与运行

```bash
python -m uav_abnormality.data.crowd_temperature \
  --input /path/to/crowd_temperature.csv --destination data/raw/crowd_temperature
python scripts/run_report_benchmarks.py --datasets crowd_temperature \
  --algorithms condition_alignment prbtd tsadc \
  --prepare --epochs 2 --seeds 42 --output runs/crowd_check
```

默认训练、验证、校准和测试均按 [目标导向攻击协议](ATTACK_PROTOCOL.md) 注入 `target_bias`（定向偏置）与 `change_suppression`（变化压制）。`false_trend` 不再作为默认异常类型：任务关注每轮估计是否被误导，轨迹连续上升本身不是危害判据。

Crowd 使用 `persistence: sustained` 持续攻击，并以 `start_offset_rounds: 1` 保留每个片段的首轮历史，从后续轮次开始攻击。受控来源池由训练阶段确定；每轮使用其中实际在场的来源，在局部少数及幅度、变化率约束下实施篡改。来源移动或缺席时不补造报告，也不要求同一联盟始终停留在同一网格。持续模式不强制攻击在短片段内结束，但仍需有可行、真正改变数值且进入评分的攻击报告；预热结束并不保证每轮都有足够参照来源。

数据没有独立温度参考，联合感知影响只能解释为相对未注入报告聚合的位移，不能据此声称真实环境误差增加。原始来源的自然异常状态仍未知，未注入报告也不因此成为经过核验的正常报告。

原始文件和导入收据位于 `data/raw/crowd_temperature/`，当前准备后的报告写入 **`data/processed/crowd_temperature_v2.csv`**。旧五种子比较使用的 `data/processed/crowd_temperature.csv` 保留原协议：6 小时、3×3 网格、32 来源、16 个时间片。该批结果中 Crowd 攻击未进入评分、校准分辨率不足的结论仍然有效，不能套用本页的新覆盖数量重新解释。新旧运行均以自身保存的配置和数据哈希区分；跨种子结果阅读见 [REPORT_EXPERIMENTS.md](REPORT_EXPERIMENTS.md)。
