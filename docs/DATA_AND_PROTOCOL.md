# 数据与评测协议

三套实验共用报告接口、数据划分和报告篡改设置，使算法差异集中在“如何判断贡献、如何估计环境”。数据准备配置位于 `configs/datasets/`，训练配置位于 `configs/experiments/`。当前实验入口采用有界、目标导向的报告攻击，详细规则见 [ATTACK_PROTOCOL.md](ATTACK_PROTOCOL.md)。

## 1. 报告与任务

一行报告由 `sequence_id, task_id, timestamp, source_id` 唯一确定。`value_*` 是数值观测，`condition_*` 是位置等采集条件。来源 ID 在不同任务间保持一致，`timestamp` 使用聚合窗口的右端点，表示这一窗口的报告已经可用。

| 数据 | 原始数据与 UAV 任务组织 | 默认规模 | 我们的方法使用的条件 |
|---|---|---|---|
| crowd_temperature（v2） | 作者基于出租车参与、位置和天气生成的温度；原来源映射为虚拟 UAV，罗马 2×2 网格内组织巡检任务 | 前 75 个训练时隙中的全部 164 个来源；189 个有报告的半小时时隙；3,106 份报告 | 报告平均纬度、经度；网格变粗后仍保留实际来源位置差异 |
| TaxiBJ | 真实区域交通流量作为环境场，8 个虚拟 UAV 动态参与并提交带轻微测量噪声的统计 | BJ15 前 8 个完整天、4 网格、半小时报告；9,814 份报告 | 网格位置和周期时间；同任务同时间条件相同，因此当前数据的条件修正为零，可观察质量、校准与信誉的作用 |
| Intel Berkeley | 实测固定传感器温度与位置，一节点对应一虚拟 UAV；另留出两节点作为查询位置 | 2004-03-01 至 03-09；8 个报告节点、5 分钟报告；18,370 份报告 | 实际平面位置 x/y；查询位置使用留出节点的 x/y |

这些数据支持报告层的低空感知任务改编；参与和任务组织由配置描述。Intel 的高度字段是模拟作业参数，TaxiBJ 的坐标是网格索引。完整原始文件保留在 `data/raw/`，默认实验子集写入 `data/processed/`，可通过数据配置扩大规模。

Crowd v2 将同一来源、网格、半小时内实际观测取均值，表示该区间的报告统计，不是提交时刻的瞬时温度真值。其 3,106 份报告来自原始 5,030 行中的 3,701 行；未选入的未来来源仍保留在原文件中。适配器不插值、不补齐来源参与。新报告路径是 `data/processed/crowd_temperature_v2.csv`，与旧的 `crowd_temperature.csv` 分开保存。旧运行中的 6 小时、3×3 网格、32 来源、572 报告仍按其原配置解释。

## 2. 四个阶段

| 数据 | 划分单位 | 训练 / 验证 / 校准 / 测试 | 基线历史窗口 |
|---|---|---|---|
| crowd_temperature（v2） | 按时间先后，40% / 10% / 30% / 20% | 75 / 19 / 57 / 38 个时隙 | 2 个时隙 |
| TaxiBJ | 按时间先后 | 50% / 12.5% / 12.5% / 25% | 8 个时隙 |
| Intel Berkeley | 整个日期 | 4 / 1 / 1 / 2 天 | 12 个时隙 |

先划分原始报告，再用训练阶段的注入前报告拟合攻击约束，并在四个划分内部各自生成攻击和构造窗口。训练、验证、校准和测试均包含攻击尝试；各阶段共用训练期确定的幅度、变化率等约束与攻击类型，测试阶段不重新估计约束。模型归一化参数仍由训练集拟合，验证集用于早停，校准集用于固定异常判定规则，测试集用于最后评测。缺测保留为掩码，时间间隔过大时中断窗口。

三种算法使用同样的历史窗口，在窗口末端评估报告。我们的方法按窗口内各时间位置完成条件对齐，在共同有效位置上计算平均距离，并要求末端来源及至少两个参照来源有效。条件缺失或参照不足时记录未评估状态，指标同步报告评分覆盖。

Crowd v2 的训练 / 验证 / 校准 / 测试报告数为 1,243 / 265 / 886 / 712，可评分窗口为 162 / 30 / 97 / 93，可评分报告为 1,042 / 186 / 731 / 630。窗口要求相邻任务轮次间隔不超过 `1800.1` 秒。来源词表仅从训练前 75 个时间片确定，其截止时刻与实际训练集一致，全部 164 个来源在训练集中出现。数据准备、划分或窗口设置变化时应重新检查此关系，以及四个阶段的评分和攻击覆盖。

## 3. 原始质量与额外攻击

crowd_temperature 与 Intel 原始文件缺少逐报告故障标签，以 `label=-1` 保存；TaxiBJ 的默认报告生成器具有已知的正常报告机制。共享模块在每个划分内选择少数非合作来源，对其数值报告实施有目的的篡改，并分别保留：

| 字段 | 含义 |
|---|---|
| `baseline_*` | 本次攻击前的原报告值；不代表原始报告一定正常 |
| `original_label` | 原始标签，未知时为 -1 |
| `injection_label` | 本次是否真正改变了报告 |
| `fault_type`, `fault_event_id` | 攻击类型及所属事件；保留字段名以兼容已有读取接口 |
| `truth_*` / 查询 `reference_*` | 下游估计评测的独立参考 |

四个阶段均显式采用 `protocol: targeted_report_attack`，默认使用 `target_bias`（定向偏置）和 `change_suppression`（压制当前观测变化）。`false_trend` 不再作为默认异常类型；连续上升或下降本身不代表每轮环境估计受到实质影响。攻击者使用受控来源当前及过去的观测构造篡改；独立真值、查询参考、未来报告和防御器输出不作为攻击输入。攻击只改变报告数值，来源身份、采集条件、时间和参与模式保持原样。

无攻击对照通过运行器的 `--no-attacks` 明确覆盖四个阶段，保存 `attack_mode: none` 与各阶段的 `protocol: none`，原报告数值不改变、实际注入标签全零。该对照重新训练并重新校准，同时保留原划分、窗口、训练预算及校准规则；它并非对已训练攻击模型只移除测试攻击，也不代表原数据中的自然异常已经消除。没有注入正例时只解释误报率、覆盖及有参考的感知误差，不把缺失的 AP/Recall/F1 补成零。完整运行和配对比较入口见 [运行指南](REPORT_EXPERIMENTS.md#无攻击实验与攻击前后对照)。

全局来源预算与每次攻击的联盟规模共同限制攻击者，并逐任务轮次检查实际参与来源中的局部攻击比例，要求严格小于一半。幅度和变化率使用训练历史尺度，取值硬界限由配置显式声明；这些约束不等同于传感器的物理规格。历史不足、局部多数、预算冲突或有效变化不足时，保留不可行或无效的尝试记录，不扩大幅度来强行产生成功攻击。

Crowd v2 使用 `persistence: sustained`，允许攻击在后续可行轮次持续开展，不要求在一个短片段内自动恢复。`start_offset_rounds: 1` 预留首轮历史，后续轮次才开始攻击。恶意来源池在训练期固定，实际联盟随其中哪些来源到场而变化；来源移动、跨网格和缺席不产生虚构报告。预留历史解决攻击起点与窗口预热重合的问题，当前轮是否可评分仍取决于真实参与覆盖，运行前须分别核查四个划分中是否存在可评分的实际篡改报告。

检测指标中的额外篡改有独立标签。默认配置同时启用 `assume_unlabelled_normal`，以未注入报告为实验背景；原数据中的未知自然故障会继续存在，因此未注入不等于经过核验的正常。模型训练使用报告与有效掩码，我们的方法再加入条件；标签只在指标计算和明确选出的校准核验环节使用。已保存运行的协议以各自 `config.resolved.yaml` 与划分记录为准；新的攻击配置不改变旧结果中 offset、spike 等故障的含义。

## 4. 校准怎样工作

PRBTD 和 TSAD-C 在独立校准集上取经验分位数，测试时固定阈值。我们的方法按窗口长度设置校准任务间隔，使同任务的选中窗口互不重叠，并在评分前按固定规则为每个校准任务选一份报告，核验其中分数最高的若干份，移除确认异常者，再用保留分数计算精确的 Label-Trim p 值。其核验预算、移除记录和保留分数随实验保存；同一核验选择之外的报告标签保持隔离。

当前时间任务具有时序相关性，因此结果用于比较该采样协议下的实测误报率。四阶段存在攻击不意味着校准已经干净，Label-Trim 的少量核验也不验证原始自然故障。时间隔离降低窗口重叠，并不证明校准与测试数据满足交换性。方法公式与核验过程见 [METHOD.md](METHOD.md)。

Crowd v2 将 30% 的时间片分配给校准，依据是有效校准轮数预算，而不是报告行数。按一小时的同任务抽样间隔，当前覆盖提供 51 个可评分校准单元；`alpha=0.05` 的核验预算最多为 2，故评分有限时移除后保留 49–51 个，运行要求至少保留 40 个。一个任务轮次只抽一份报告，增加同轮来源不会直接扩大校准池。p 值最小步长是 `1 / (保留单元数 + 1)`；19 个单元仅是允许 p 值达到 0.05 的分辨率下限，不是校准质量保证。旧五种子比较中的 Crowd 每个运行只有 3 个保留单元，最小 p 值 0.25，不能报警；该限制不能用新配置的数据量消除或重新解释。

## 5. 环境估计和信誉

TaxiBJ 的 `truth_*` 保存原交通场，可直接计算共同任务估计误差。Intel 节点 9、10 完全留出，测量仅在评分后评价查询位置的估计；它们提供独立测点参考，并非经过核验的绝对环境真值。crowd_temperature 主要评估报告篡改检测及信誉轨迹；其攻击影响只能表述为相对于未篡改报告聚合的位移，不能据此声称真实环境误差增加。

公共后处理对所有方法采用相同中位数或固定反距离加权，用来观察筛掉异常报告后的变化。我们的方法还按 proposal 将报告对齐到目标条件，以 `(1-A) × 旧信誉 × 当前质量` 计算权重并做加权中位数。公共后处理和方法原生估计分别保存。

信誉按独立序列的时间顺序推进。我们的方法对每个有效任务先估计环境、再更新信誉，同期任务按固定任务 ID 顺序处理。PRBTD 对同期任务先共享旧信誉，再平均各任务的更新提议。两者的缺席或未评估来源均保持原值，不同划分和独立序列分别初始化。

## 6. 指标与文件

异常检测使用逐报告 AUROC、Average Precision、Precision、Recall、F1、FPR，同时保存逐来源和逐故障结果。异常分数越高越异常；连续质量越高越可靠。未知原始标签通过独立注入指标区分，类别不足的指标记为 `null`。

环境估计报告 MAE、RMSE 和可用比例；有效来源不足的任务记为缺失。攻击评测区分“报告被篡改”“无防御时联合估计受到实质影响”和“防御后仍有实质影响”。影响阈值使用报告原单位，在评测前固定；不根据测试结果调低阈值或删除失败尝试。少数来源对中位数可能没有实质影响，这应记为攻击未奏效，不能改换聚合器制造成功。

检测指标同时检查攻击结束后的恢复阶段：历史窗口或信誉可能继续受先前攻击影响，此时未篡改报告上的告警计入恢复阶段误报。质量分析检查质量与独立误差的排序关系，信誉轨迹用于观察来源变化。多随机种子结果汇总均值、标准差与有效运行数。具体运行命令与文件阅读顺序见 [REPORT_EXPERIMENTS.md](REPORT_EXPERIMENTS.md)。
