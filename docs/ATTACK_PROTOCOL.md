# 目标导向的少数来源报告攻击

本协议用于检验：少数非合作 UAV 在报告数值仍符合预设经验约束时，能否有目的地影响联合感知，以及质量评分、异常过滤和信誉能否减轻这种影响。攻击发生在报告提交环节，不修改模型、不设置后门触发器。真实数据仍按 [DATA_AND_PROTOCOL.md](DATA_AND_PROTOCOL.md) 的任务与划分组织。

## 1. 四个阶段均包含攻击

三个实验配置在 `corruption.train`、`validation`、`calibration`、`test` 中均显式设置 `protocol: targeted_report_attack`。四个阶段默认使用定向偏置与变化压制两类攻击和统一约束；训练数据允许被污染，验证与校准也不以“无攻击”为前提。

先划分注入前的原始报告，再只用训练划分拟合约束参数，并将同一份参数用于各阶段。各阶段的攻击在自己的时间范围内生成，历史不跨越独立序列或数据划分。模型训练仍只读取报告、有效掩码和对应条件；攻击标签、参考真值以及事件审计字段不作为模型输入。

若目标攻击协议在训练划分中没有实际产生任何篡改，运行器会明确报错，而不是继续训练并将其描述为含攻击训练。Crowd v2 还启用严格预检：四个阶段都须有进入评分的实际篡改，校准保留单元至少为 40。不可行尝试仍照常保留，不能把“已配置攻击”当作“必然实现污染”。

`baseline_*` 保存本次攻击之前的报告。TaxiBJ 的报告生成机制及交通场参考已知；Crowd 和 Intel 的原始自然故障状态未知，故 `baseline_*` 不应称为“干净真值”。默认 `assume_unlabelled_normal` 只定义未注入背景的指标口径，不是质量核验。

三个算法在同一数据集、种子和配置下读取相同的划分及攻击记录。本轮 `runs/crowd_sustained_5seeds_20261113` 单独重跑 Crowd 的三个方法与五个种子；旧 `runs/targeted_attacks_5seeds_20261113` 的 45 次结果仍采用当时保存的三类攻击及危害判据。TaxiBJ、Intel 的当前配置已更新默认类型和评估目标，但本轮没有重跑它们，不能将新旧结果混合。

## 2. 攻击者能控制和看到什么

攻击者只能修改被选中的来源原本会提交的 `value_*`。来源身份、采集条件、任务、时间戳、正常参与情况与缺测不变，也不增加虚假来源。

默认 `source_fraction: 0.25` 确定全局受控来源预算，`source_selection_seed` 固定来源选择。事件尝试使用 `coalition_sizes: [1, 2]`；全局预算、事件联盟规模和当前轮次的实际参与共同决定能否实施。每个任务轮次都检查局部攻击比例，`max_local_fraction` 必须小于 0.5。全局只有少数受控来源，不保证某个稀疏任务里它们仍是少数，后者需要单独检查。

生成攻击可以使用受控来源当前和过去的原始观测，以及预先确定的训练期约束。攻击者不能读取其他未受控来源的观测值、未来报告、独立参考、异常标签、校准分数或防御器输出。参与身份可用于执行实验预算检查，不能借此读取诚实来源数值。TaxiBJ 的 `truth_*` 和 Intel 查询节点的 `reference_*` 只在生成结束后进入评测器。

联盟规模、强度与事件计划来自固定配置和随机种子，不按某个防御器的测试结果逐次调整。所有方法承受同一攻击轨迹，便于比较防御效果。

## 3. 两类默认攻击及攻击意图

| 类型 | 目的与构造 | 应观察的影响 |
|---|---|---|
| `target_bias` | 对受控报告施加同一预设方向的有界偏置，试图让当前联合估计偏高或偏低 | 当前轮次的绝对参考误差增量；有向位移作为机制诊断 |
| `change_suppression` | 根据受控来源的因果历史基准缩小当前变化，试图隐瞒当前环境的变化 | 当前轮次的绝对参考误差增量；变化幅度损失作为机制诊断；历史不足或变化太小时可能无效 |

异常类型描述攻击者的构造与意图，不保证每次实施都产生危害。持续上升或下降既可能是真实环境变化，也可能没有影响最终估计，因此 `false_trend` 不再列为独立的默认主攻击。代码仍保留该类型以复现旧运行；其结果不能与当前两类默认协议混为一谈。温度或流量被篡改后，是否真正有害均按第 5 节的当前轮次估计误差判定。

Crowd/Intel 的物理单位是温度，TaxiBJ 是所选流量通道。当前仓库没有定义真实火灾报警、拥堵控制或飞行调度策略，因此只评价感知估计，不虚构业务阈值或操作后果。短序列、稀疏参与、历史不足和局部少数约束仍可能阻止某类事件，必须区分配置的尝试、可实施事件和实际改变的报告，不能为了凑齐类型而违反约束。Crowd v2 已改为 189 个有报告的半小时时隙；旧版只有 16 个六小时时隙的限制属于历史结果。

## 4. 幅度和过程约束

约束从训练划分的注入前数据拟合，并在验证、校准、测试中冻结。当前实现以各观测特征的训练标准差为尺度，常量特征使用 `1e-6` 下限。三套实验各自的四个阶段共用以下配置：

```yaml
constraints:
  target_delta_sigma: 0.75
  max_delta_sigma: 1.0
  max_delta_step_sigma: 0.25
  min_effect_sigma: 0.1
```

| 字段 | 含义 |
|---|---|
| `target_delta_sigma` | 期望偏置的训练标准差倍数，仍须满足其他约束 |
| `max_delta_sigma` | 单份报告相对原值的最大改变量 |
| `max_delta_step_sigma` | 同来源相邻有效报告的攻击改变量增量上限，限制篡改过程的突变 |
| `min_effect_sigma` | 启动实质核心篡改的最小改变量；已启动事件的平滑退出可低于该值 |
| `hard_bounds` | 可选原单位取值范围；TaxiBJ 设置 `value_0: [0, null]`，流量不低于零 |
| `max_report_step_sigma` | 可选相邻报告步长限制；默认不启用 |

`max_delta_step_sigma` 限制的是攻击增量的变化，不是把真实环境变化强行限制为平滑。攻击日历支持以下两种设置，均不能读取未来值来保证可行：

- **有限时长 `bounded`：** `duration` 包含主要篡改和退出阶段，末轮改变量回到零。TaxiBJ、Intel 保持既有日历，分别为 8、12 轮；若缺席或原值异常使连续退出不可行，记录中止原因。
- **持续 `sustained`：** 不强制在一个固定短片段末尾回到零。Crowd v2 四阶段都使用该模式，`start_offset_rounds: 1` 保留首轮历史，`report_fraction: 1.0` 计划其后所有可用轮次。受控来源暂时缺席时保留状态，待真实报告再次出现后才继续；不补造报告。

Crowd 同时使用 `source_selection_mode: present_compromised_pool`。训练期固定恶意来源池及身份优先顺序，每轮仅从实际在场成员中选择，联盟规模与局部少数约束仍然有效。未入选来源正常提交时，其攻击增量回到零；若这种退出超过增量步长约束，记为 `attack_forced_abort`，整个事件的 `feasible` 为假。后续可行轮次允许重试，但中止记录不会被清除，先前实际发生的篡改也不回滚。`source_ids` 可包含整个事件先后尝试的多个成员，实际同时参与规模看 `max_active_coalition_size`，不能将两者混淆。

`source_fraction` 控制受控来源的选择数量。沿用的字段名 `report_fraction` 控制每个连续任务时间段的计划攻击轮次比例，不是总报告的实际污染率。有限时长模式下，TaxiBJ、Intel 仍在训练、验证、校准设为 0.05，测试设为 0.30；每段请求 `max(1, round(可用轮数 × report_fraction))` 轮，比例为零时请求零轮，再取完整事件而不强行截断退出阶段。持续模式下，预算安排在预热之后的连续尾段；Crowd 的比例为 1.0，表示所有预热后的轮次都纳入计划，实际污染仍受参与、历史、局部少数和幅度约束限制。

独立序列、阶段边界和任务缺测间隙仍不可跨越。在有限时长模式中，时间段尾部至少两轮时可以形成较短事件；如果只剩一轮且前块长度大于两轮，调度从前块移一轮以构成两轮尾块。无法这样分配的孤立尾轮不强行启动事件，而只含一轮的独立时间段仍保留不可行尝试。兼容保留的 `false_trend` 还需要至少两个核心轮次。

类型轮换先覆盖配置类型的单来源尝试，再轮换联盟规模。有限时长模式的 `min_attempts` 默认等于类型数，在日历允许时预先补足阶段内的尝试数。计划仍只依赖身份和时刻，不根据未来值、防御结果或已发生事件是否成功来补抽。完整事件取整和最少尝试数会使实际计划轮次比例超过配置值，而动态参与、局部少数、幅度门槛和不可行事件又会减少实际修改报告数。

阶段注入元数据中的 `total_task_rounds` 是去重后的 `(sequence_id, task_id, timestamp)` 数量；`scheduled_round_fraction` 是计划事件覆盖的轮次比例，`changed_round_fraction` 是至少有一份报告被修改的轮次比例，`round_budget_excess` 记录超过请求预算的轮次数。`minimum_attempt_extra_events` 与 `unfilled_minimum_attempts` 分别记录日历预补尝试和仍无法补足的数量。实际报告污染率 `injected_report_fraction = injected_reports / total_reports`，尝试涉及报告比例为 `attempted_report_fraction`；不能用轮次比例或配置的 0.05/0.30 代替。

这些是经验约束，不是传感器的物理可行性证明。Intel 原始日志可能已经含有自然异常，因此宽取值范围本身不能保证新报告合理；必须同时读取训练期拟合参数、各事件实际改变量和约束检查结果。配置的原单位限制及历史统计应随运行保存，供复查。

约束不可满足时，该次尝试记录原因并保留未修改值。核心修改达不到 `min_effect_sigma` 时，不启动新的实质篡改；已启动事件的平滑退出可能只剩较小改变量，这些非零修改仍有注入标签，`attack_material_effect` 另行标记是否达到幅度门槛。数值完全未变的报告不标为被篡改。不可行、未产生有效修改、以及修改后未产生联合影响的情况都保留在统计中，不事后删掉失败尝试，也不根据测试结果放宽预算。

## 5. “篡改成功”与“防御成功”分别衡量

首先用原报告 `baseline_*` 和篡改报告构造相同公共聚合器下的两条估计，再使用防御器保留的报告进行同口径聚合。TaxiBJ 沿用普通中位数，Intel 沿用固定反距离加权；不会为了让攻击奏效而临时换成更易受影响的聚合器。Condition Alignment 的原生对齐、质量和旧信誉加权估计仍单独报告。

需要区分三个层次：

1. **报告篡改：** 数值实际发生了有效修改。报告级检测的阳性标签按这一事实定义。
2. **无防御时的实质影响：** 有独立参考时，当前轮次的绝对估计误差相对未注入对照增加，并达到预设原单位门槛。不能把恰好修正原偏差的位移说成破坏。
3. **防御后的残余影响：** 相同事件经过防御后还剩多少位移或参考误差，是否仍超过门槛，以及是否失去估计覆盖。

少数报告即使被有目的地篡改，也可能不能推动中位数；这属于该事件未形成实质影响。检测器不能凭“没有告警”证明失败，攻击也不能凭“报告改过”证明成功。反过来，防御器若通过拒绝全部报告消除误差，必须同时报告估计缺失，不能把缺失当作零误差或防御成功。

TaxiBJ 可以使用交通场 `truth_*` 判断估计误差是否增加。Intel 使用留出节点温度作为独立测点代理参考，其自然质量仍未经逐报告核验。Crowd 没有独立环境真值，只报告相对于原报告聚合的位移，不将其命名为已证实的真实环境损害。

当前三个配置使用 `evaluation.attack_harm_objective: instantaneous_error`。对有独立参考的每个时刻和查询点，比较：

```text
误差增量 = |攻击后估计 − 参考| − |未注入对照估计 − 参考|
```

增量达到 `evaluation.attack_harm_threshold` 才算该轮产生危害；不再要求偏置方向、参考稳定、持续趋势或变化压制机制同时通过额外门槛。它们仍是机制诊断量。当前 Crowd/Intel 门槛为 0.2 °C，TaxiBJ 为 1 个流量单位，`attack_min_harm_rounds: 1` 表示一个任务轮次达到门槛即可，同一轮的多个查询点不重复计数。这些是实验效应门槛，不代表真实业务危险线。

Crowd 参考缺失时，真实误差增量、实质损害与保护成功仍不可判定，相关指标为 `null`。另列位移代理：相对于未注入对照估计的绝对位移是否达到相同门槛，以及防御后的位移；该表用于描述输出受扰动程度，不叫作已证实的真实误差或防御成功。

旧 checkpoint 若没有 `attack_harm_objective`，保留 `mechanism_specific` 判据：定向偏置要求有向位移与误差增加，变化压制要求真实变化被压低且误差增加，虚假趋势要求参考较稳定而估计产生有向变化及误差增加。旧五种子配置还要求至少两轮达到门槛。重新分析旧结果不会自动切换为当前判据，两个版本的有效攻击数量不能直接合并。

报告结果时应列出阈值、持续轮数、比较的有效轮次及覆盖分母。不得在看到测试结果后调低门槛，或只留下成功事件再报告攻击成功率。

## 6. 时序恢复和校准限制

历史窗口内的攻击会影响后续未篡改报告的评分，信誉也需要时间恢复。`window_contains_attack` 标记同来源、同任务的当前历史窗口是否包含实际修改的报告；`evaluation_phase` 区分 `active`、`recovery` 与 `background`。恢复误报率只统计当前未被篡改且窗口含攻击的已评分报告，普通背景误报率只统计当前及该来源窗口均无攻击的已评分报告。它们不能替代对跨来源参照影响和长期信誉恢复的进一步分析。原始标签未知时，这仍是对未注入背景的误报口径。

校准集也包含攻击。Label-Trim 按固定预算核验所选报告的本次注入状态，未选择标签保持隔离；核验不会自动清除原始自然故障，也不证明交换性。旧 Crowd 五种子运行只有 3 个保留单元，最小 p 值 0.25，无法报警。Crowd v2 改为半小时、2×2 网格、40% / 10% / 30% / 20% 划分及一小时校准间隔；当前覆盖可提供 51 个可评分单元，最多移除 2 个，严格检查实际保留至少 40 个。该修正解决旧协议的分辨率阻断，但不是低误报率的理论保证。

## 7. 审计文件与反事实口径

| 产物 | 用途 |
|---|---|
| `attack_profile.json` | 训练期拟合的特征尺度、训练来源选择、约束、显式硬界限和样本计数，四阶段共享 |
| `split_manifest.json` | 划分与注入元数据，核对每种尝试、实际修改及失败原因 |
| `attack_audits/<阶段>/metrics.json` | 模型训练前对该阶段的公共无防御聚合进行影响审计 |
| `attack_audits/<阶段>/attack_events.csv`、`attack_rounds.csv` | 对应阶段的事件及逐轮记录 |
| 测试目录 `attack_events.csv`、`attack_rounds.csv` | 测试事件的无防御、公共过滤防御及可用的原生估计比较 |
| `baseline_predictions.csv` | 对同一测试划分移除本次注入后，使用同一 checkpoint 重新评分的结果 |
| `baseline_native_environment.csv` | Condition Alignment 在上述反事实轨迹上的原生估计 |

反事实评测使用已经在含攻击训练集上训练的同一个 checkpoint，模型参数和校准规则均固定；它不重新训练干净模型。将 `value_*` 恢复为 `baseline_*` 后，从序列起点重置并重新推进信誉，以比较测试阶段额外篡改造成的影响。原始自然故障仍保留，因此文件名中的 `baseline` 或逐轮字段中的 `clean` 只表示移除了本次生成的攻击。

测试汇总位于 `metrics.json` 的 `attack_evaluation`。`attempt_events` 是尝试数，`feasible_events` 是可行事件数，`assessed_events` 是能判定无防御影响的事件数，`effective_events` 是达到实质影响定义的事件数；实际修改报告数另见事件的 `changed_reports`。`defended`、`native` 分别报告公共防御与原生估计的残余影响，以及在原本有效的攻击中完全可评估且得到保护的数量和比例。没有有效攻击、没有参考或缺少估计时，部分比例为 `null`，不是零误差。

`detection.detected_event_rate` 保留未检出尝试在分母中，`mean_delay_seconds` 只对检出的事件计算首次告警延迟；两者应共同阅读。`false_positive_rate.background` 和 `.recovery` 各保存样本数 `n`、误报数 `fp` 和 `fpr`，`per_kind` 按攻击类型重复事件统计。协议检查和运行步骤见 [REPORT_EXPERIMENTS.md](REPORT_EXPERIMENTS.md)。
